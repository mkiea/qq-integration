# 唱歌与音色：别人怎么做的，我们能走哪条

> 写于 2026-11-04。起因：主人问「看看别人唱歌和音色怎么调的和实现的」。
> **口径声明**：下面分三类标记 ——
> 【官方】厂商文档/仓库 README 明写；【社区】第三方文章/汇总（数字常互相矛盾，我不复核）；
> 【推算】我根据硬件与接口推的，没有实测。

## 一、先说结论

| 想要 | 现实可行的路 | 代价 |
|---|---|---|
| 换音色（她的声音像谁） | **零样本克隆**：GPT-SoVITS（5 秒参考音频） | 已在我们代码里（`ttsProvider: local`），只差把服务跑起来 |
| 唱一段（有旋律） | **要么念唱，要么离线预生成** | 实时 SVS 在 8GB 卡上不现实 |
| 翻唱（拿别人的歌换成她的声音） | so-vits-svc / RVC | 需要**别人唱的人声**+训练，且版权与伦理问题最大 |

一句话：**音色是已经能做的事**（只差部署），**唱歌是"能做到但不像歌"或"像歌但不实时"的二选一**。

## 二、唱歌的三条技术路线

### 路线 A：念唱（TTS + SSML 调音高）—— 我们现在的做法

用 TTS 念歌词，靠 SSML 的 `<prosody pitch rate>` 制造起伏。一句一个 `<s>`，pitch 按旋律循环。

- **优点**：零依赖（有 TTS 就能用）、即时、成本忽略、不需要谱面。
- **上限**：它**不是歌**。音高变化是"念得有起伏"，不是"唱在调上"——因为 TTS 的基频由文本韵律决定，pitch 只是整体平移，音节之间没有真正的音程关系。
- 【官方】Azure 的 style 列表里**没有 singing**：`advertisement_upbeat / affectionate / angry / assistant / calm / chat / cheerful / customerservice / depressed / disgruntled / documentary-narration / embarrassed / empathetic / envious / excited / fearful / friendly / gentle / hopeful …`（还有 shouting、whispering、laughing 这类副语言标签）。
  ⇒ **这不是我们没找到，是云 TTS 普遍不做唱**。（我们 `lib/tts.js` 的注释即以此为依据。）

### 路线 B：SVS（歌声合成）—— 给歌词 + 谱面，模型直接唱

代表项目 **DiffSinger**（AAAI 2022）+ 编辑器 **OpenUtau**。

- 【官方/仓库】输入是**音符（MIDI）+ 音素**，不是纯文本；模型链路是
  `语言学模型 → 声学模型（mel 谱）→ 声码器（波形）`，另有 pitch / variance 模型预测基频弯曲与气声能量。
- 也就是说：**必须有人把旋律写成谱**。纯文本"唱首歌"在 SVS 里不成立——没有音高序列就没法唱。
- 生态：OpenUtau 里 DiffSinger 是可选渲染器之一（还有 Classic/Enunu/Vogen），
  歌手包是 `dsconfig.yaml` + 若干 ONNX 模型（acoustic / vocoder / pitch / variance）。
- 做她的音色：需要**用她的声音训练一个 SVS 歌手包**（数据集是"唱歌"录音，不是说话录音）。

**对我们的意义**：如果她真的"会唱歌"，路径是**离线先合成几首**（OpenUtau 里排好谱 → 渲染成音频文件），
运行时用 `!唱 <曲名>` 直接播文件。这样：
- 不需要实时推理（8GB 卡无所谓）
- 不需要模型常驻
- 但**曲目是固定的**（唱不了任意歌词）

### 路线 C：SVC（歌声转换/翻唱）—— 保留原唱，换成她的音色

代表项目 **so-vits-svc**（AI 翻唱那一波的底座）、**RVC**（检索增强版，更轻更快）。

- 【社区汇总，数字互相矛盾，谨慎看】
  - so-vits-svc：干声 1–5 小时、显存 8–12GB、非实时（需 ONNX/TensorRT 加速）；
    也有文章说"5 分钟即可迁移学习"——**两条说法差两个数量级，我不采信任何一条**。
  - RVC：1–2 分钟可出"能听出是谁"的模型（推荐 10–20 分钟）、训练 4GB 起、推理可实时（<200ms）。
  - 定位差异：RVC 追求**快与实时**，SVC 追求**高音区/颤音的保真**。
- **硬约束**：SVC 需要**一段别人唱好的干声**作为"内容源"。她没有可唱的歌 = 没有源。

**对我们的意义**：这条路是"把某首歌换成她的声音"，不是"她自己唱歌"。
而且它必然踩到**原唱版权**与**音色授权**两条线——**不建议**用在会对外发布的地方。

## 三、音色的四档做法

| 档 | 做法 | 代表 | 需要什么 | 能不能离线/本地 |
|---|---|---|---|---|
| ① 预设音色 | 从厂商音色表里挑 | Azure 700+、OpenAI 六种 | 只有 API key | 云端 |
| ② 零样本克隆 | 给 3–10 秒参考音频，模型当场模仿 | **GPT-SoVITS**、CosyVoice、F5-TTS、Fish Speech | 一段干净的人声 + 本地/云服务 | ✅ 全本地可行 |
| ③ 少样本微调 | 几分钟到几十分钟数据，训一个专属权重 | GPT-SoVITS 微调、CosyVoice 微调 | 数据 + 训练（几十分钟~几小时） | ✅ |
| ④ 声音转换 | 不改内容，只换音色 | RVC / so-vits-svc | 源音频 + 目标音色训练 | ✅（但要 GPU） |

【社区汇总，仅作选型参考】几个主力项目的关键数字：

| 项目 | 克隆 | 显存 | 速度 | 许可 |
|---|---|---|---|---|
| GPT-SoVITS | 5 秒零样本 / 1 分钟微调 | **4GB 可训练** | RTF 0.028（4060Ti） | MIT（可商用） |
| CosyVoice | 3 秒零样本、18 方言 | ~3.5–8GB | 流式首包 ~150ms | Apache-2.0 |
| F5-TTS | 数秒零样本 | 2.5–4GB | RTF 0.039（L20+TRT） | 代码 MIT / **权重 CC-BY-NC** |
| Fish Speech | 10–30 秒免微调 | 4–6GB | 快 | **研究许可，非商用** |

⚠️ **两个坑**：
1. **许可证不是都允许商用**。F5-TTS 的权重是 CC-BY-NC、Fish Speech 是研究许可。要用在公开发布的东西上，先看许可。
2. **零样本会连噪声一起学**（社区多次提到）：参考音频里有底噪/混响，模型会把它当成"音色"的一部分。

## 四、落到我们这台机器上

硬件：**RTX 4060 Laptop 8GB** + 33GB 内存（见项目记忆）。

| 方案 | 8GB 够吗 | 实时吗 | 我们要改什么 |
|---|---|---|---|
| Azure 预设音色 | 不占显存 | 是（云） | 已支持（`ttsProvider: azure`） |
| Azure 念唱 `!唱` | 不占显存 | 是 | ✅ 已做（⊕³³） |
| GPT-SoVITS 零样本 | 【推算】4GB 可训、推理更省 ⇒ **够** | 【推算】RTF 0.03 级别，够用 | **代码已支持**：`ttsProvider: local` + `ttsLocalUrl` 指向 api_v2 服务 |
| CosyVoice 零样本 | 【推算】3.5–8GB，**贴边** | 是 | 要写一个适配器（接口不是 api_v2） |
| so-vits-svc 翻唱 | 【社区】8–12GB，**8GB 偏紧** | 否（需加速） | 要新写一条"音频→音频"的链路 |
| DiffSinger SVS | 【推算】ONNX 推理不难，但**要先有谱** | 离线即可 | 离线预生成 + `!唱 <曲名>` 播文件 |

### 我的建议（分三步，每步都能单独收工）

1. **先把她自己的声音做出来**（音色）——部署 GPT-SoVITS api_v2，配 `ttsProvider: local`。
   代码侧**不用改**，这是既有能力一直没启用。收益最大、风险最低。
2. **想要"真唱"，走离线预生成**——OpenUtau + DiffSinger 排几首，导出音频放 `qq-voices/songs/`，
   `!唱 <曲名>` 播文件。**不做实时 SVS**：8GB 卡 + 冷启动延迟 + 歌长几分钟，实时没有意义。
3. **不做 SVC 翻唱**（除非明确只是自己听）——它需要别人的干声，且版权/音色授权两条线都碰。

## 五、我们和"别人"的差别，一句话

别人做的是**产品**（一个输入框、一段参考音频、一个播放按钮）；
我们要的是**她**——所以真正的约束不是"模型多强"，而是：

- 她不能为了一句语音等 30 秒（对话节奏）
- 她不能每次都唱同一首（除非是"她最近在哼的歌"这种人设设定）
- 她的声音要**稳定**（今天晓晓明天云希，就不是"她"了）

⇒ 音色一旦定了就别乱换；唱歌如果要加，**当作"她会哼几首固定的歌"**，比"任意歌词实时唱"更像人。
