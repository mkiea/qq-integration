# 向导写入后宿主会不会热重载（2026-11-05 实测）

> 结论先说：**会**。写完 `cordis.patch.yml` 后宿主自动重载插件，桥重新 start、Waylay 重连，
> 全程不需要重启任何进程。**代价是一次短暂断线（实测 6–10 秒）**。

## 怎么验的

| 步骤 | 操作 |
|---|---|
| 1 | 记录基线：桥日志 mtime `21:07:08`；6700 对端 `127.0.0.1:60775` ESTABLISHED |
| 2 | 用向导 API 写一个**无害变更**：`allowGroups` 里加一个假群 `100000099` |
| 3 | 等 15 秒，看日志与连接 |
| 4 | 用向导 API 写回原值，确认恢复 |
| 5 | `cp` 备份覆盖，确保字节级还原 |

**为什么挑 `allowGroups` 加假群**：它只影响"哪些群允许触发"，加一个没人说话的假群 = 零副作用；
而 `botQq` / `allowUsers` / `cwd` 改了都有真实影响。

## 证据

**① 桥日志（写完后 6–10 秒内，整条 start() 流程重跑）**

```
13:20:06.691Z file canary planted: ...\qq_chat\q...
13:20:06.707Z injection channel armed: ...\qq_chat\qq-inject.jsonl
13:20:06.708Z admin command channel armed
13:20:06.709Z proactive scheduler started (60s, dry=false, ...)
13:20:06.720Z bio-clock loaded: ...\qq_chat\bio-clock.mjs
13:20:06.731Z proactive armed for 3 chat(s)
```

**② 6700 连接对端端口变了**（重连的硬证据）

```
写前：127.0.0.1:60775 → 6700  ESTABLISHED
写后：127.0.0.1:60775 → 6700  FIN_WAIT_1（旧连接在断）
      127.0.0.1:62829 → 6700  ESTABLISHED（新连接）
```

## 对用户的含义

| 事 | 说明 |
|---|---|
| 要不要重启宿主 | **不用** |
| 会不会掉线 | **会，6–10 秒**（桥重新 start + Waylay 重连） |
| 正在进行的回合 | 会被中断（`pendingTurns` 里那条会走金丝雀兜底或丢弃） |
| 改配置的频率 | **别连点**。一次保存 = 一次重连，值没变时向导会拦下来（幂等） |

## 顺带验到的一件事：格式会被规整

`allowGroups: [ 345****, 497**** ]`（带空格）写入后变成 `[345****,497****]`（无空格）——
**值一样、文本不同**。所以：

- 只比文本判"要不要写"会**误判成有变化** → 每次保存都改文件 → 每次都重连
- 我们的 `writeSetup` 是**比值**（`join(',')` 后比较），值没变直接返回「配置没有变化，未写入」

## 还没验的

- `bare-json` 落点：只有单元测试覆盖，**没有真实宿主读它**（目前没有自研宿主）
- 宿主重载的**失败路径**：如果写出的 YAML 非法，宿主会拒绝加载 —— 这个没构造过（`upsertPatchValue` 有严格的缩进/键位约束，且写入前留 `.bak-setup`）
